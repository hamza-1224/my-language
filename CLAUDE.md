# My Language (my-language): notes for future changes

- Static web app served by GitHub Pages from `main` at https://hamza-1224.github.io/my-language/
- `index.html` (page shell), `app.js` (the tutor), `sync.js` (sign-in, Supabase sync, demo, offline cache, updates, feeds), `style.css`, and `data/`: `french.js` + `persian.js` (levels, guide, older core word lists), `frgrammar.js` + `fagrammar.js` (more lessons; `drill` names a drill in `drills.js`), `frvocab.js` + `favocab.js` (generated, see below), `drills.js` (grammar questions built from the learner's words), `reading.js` (A1/A2 texts and per-level resources). Data file names have no hyphens: the installed iPhone/Mac apps' update code only inlines `[a-z]+.js`. `vendor/supabase.js` is supabase-js 2.118.0 (UMD). Font: `fonts/NotoNastaliqUrdu.ttf` (OFL).
- Data lives in the same Supabase project and table as My Budget and Kanban (`itgujuuslkymplwfxmft`, `public.docs`), as three documents: `zb_state/settings` {lang, script}, `zb_state/fr`, `zb_state/fa`, each with a `ts`. Never touch other apps' collections. Offline edits on two devices are merged with `mergeLang` (per card: more reps wins).
- Same origin as My Budget and Kanban on github.io: keep every localStorage key prefixed `zb.` and the service-worker cache prefixed `my-language-`. Sign out uses `scope:"local"`.
- Layout: all levels are open (no locking). Tabs Learn (level tabs → Vocabulary, Grammar, Reading, Watch & listen), Practice, Read, Progress (word bank), Guide. No Write tab. Card ids: words `v:<word>`, grammar questions `g:<lessonId>:<i>`; keep them stable.
- Word lists: edit `vocab/<lang>-<level>.txt` (`# Topic`, then `word | english` for French, `word | english | everyday Hindi | Hindi spelling of the shared word` for Persian) and run `python3 scripts/build_vocab.py fr fa` (needs `pip install espeakng-loader phonemizer-fork`). Persian has lists for A1–B2; C1/C2 use the core lists in `persian.js`.
- Weekly reading: `.github/workflows/feeds.yml` runs `scripts/fetch_feeds.py` every Monday and force-pushes `fr.json`/`fa.json` (`{week, levels: {B1..C2: [6 articles with topic]}}`) to the `feeds` branch; the app reads them from raw.githubusercontent.com (cached in `zb.feed.<lang>`). A1/A2 use `data/reading.js`. Articles and texts marked as read go in `P.saved`.
- Persian audio: `.github/workflows/audio.yml` records every Persian text with edge-tts (`fa-IR-DilaraNeural`) into `audio/fa/<first 16 hex of sha1(text)>.mp3`; the app normalises the text the same way (`/` and `_` to spaces, collapse spaces, trim). Add a Persian source file to `scripts/audio_texts.js` and the workflow paths if you create one.
- Interface and explanations are in English. Urdu/Hindi (the learner picks, `S.script`) appear only for pronunciation and comparisons, and must be everyday spoken Urdu/Hindi, not formal or Sanskritised. Persian data: core vocab in `persian.js` `[fa, translit, english, urdu, hindi]`, big lists in `favocab.js` `[fa, translit, english, hindi_everyday, hindi_shared, topic]` (Urdu is derived in `toUrdu`; `v[0]` is the card id, keep it stable), grammar `{id, t, x, cmp:[ur,hi], ex:[[fa, translit, en]], q}`.
- Look: calm and professional (soft neutrals, one sage-green accent, no uppercase, light shadows, dark mode), full-screen practice with a start screen and summary. No Duolingo assets. Illustrations are Fluent Emoji 3D PNGs in `img/` (MIT), flags from flag-icons (MIT), font Nunito (OFL). Don't draw custom art.
- No AI calls in the hosted app (the laptop version's AI features were removed). No analytics.
- Demo: "Try the demo" uses a local store (`zb.demo.data`, `zb.demo.on`), never the database.
- Releasing a change: bump the version in **three places together**: `version.json`, `APP_VERSION` in `sync.js`, and the `CACHE` name in `sw.js`.
- Never commit personal data, backups or progress.json. Only the publishable key belongs in `config.js`.
- iPhone app: `native/` (Capacitor 8, appId io.github.hamza1224.mylanguage), Mac app: `desktop/` (Tauri 2). `native/assemble.mjs` writes the stylesheet and scripts into one `app.html` behind `native/loader.html`; at runtime `ZB.inlinePage` builds the same page from the website for updates (`zb.native.app`). Workflows build `My-Language.ipa` (release `iphone-app`) and `My-Language.dmg` (release `mac-app`) when those folders change.
